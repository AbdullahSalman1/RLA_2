Team contributions — Delivery routing project

Abdullah Salman — Routing algorithm
- Role: Implemented the core routing logic and simulation engine used by the CLI and dashboard.
- What he implemented:
  - Nearest-neighbour based route builder with priority locking (critical stops delivered first), functions in `main.py` such as `_nearest_neighbor_route`, `build_route`, `_route_total_distance`, and `simulate_route`.
  - Raw-order and optimized-route comparison, distance calculation and basic route simulation (arrival/departure times, late detection, driver shift checks).
- Libraries/tech used: Python, requests (for ORS API calls), openpyxl (for reading Excel data); algorithms operate on distance/duration matrices returned by OpenRouteService.
- Why / how it fits: This component turns assigned orders into ordered delivery sequences and produces metrics (km, duration, late stops) used by the dashboard and the HTML report.

Saim — Constraints and assignment logic
- Role: Implemented business constraints and the order-to-vehicle/driver assignment logic used both in the CLI and the Streamlit dashboard.
- What he implemented:
  - Vehicle assignment rules (cold-chain → refrigerated vans, suburban → large vans, city → small vans) and capacity checks (max stops per vehicle) in `main.py` (`assign_orders_to_vehicles`) and reinforced in `dashboard.py` (`_assign_orders_to_vehicles`).
  - Driver assignment rules (refrigerated-certified drivers for refrigerated vehicles, simple first-available fallback) in `main.py` (`assign_drivers`) and `dashboard.py` (`_assign_drivers_to_vehicles`).
  - Data normalization and validation for orders, vehicles, and drivers in `dashboard.py` (`normalize_*_df` functions), including time-window parsing and boolean coercion.
- Libraries/tech used: Python, pandas (dataframes and normalization), openpyxl (Excel parsing through pandas), standard library utilities.
- Why / how it fits: Provides the business rules that ensure correct vehicle/driver matching, enforces hard constraints (cold chain) and soft preferences, and prepares clean input for routing.

Divine — Frontend and reporting (Streamlit)
- Role: Built the Streamlit-based frontend, interactive dashboard, visualization and HTML route report export.
- What she implemented:
  - Full Streamlit app in `dashboard.py` with file upload widgets, editable tables (st.data_editor), filters, KPIs, and interactive charts (Plotly Express).
  - Map visualizations and printable HTML route report generation (Leaflet maps embedded in HTML, `report_html` construction, `st.download_button` for report export).
  - UX touches: custom CSS, responsive layout, route tabs per vehicle, and helpful validation messages and progress spinners.
- Libraries/tech used: Streamlit (UI), pandas (data handling), plotly (charts), plotly.express, Leaflet (client-side maps embedded via HTML), uuid/tempfile for report handling.
- Why / how it fits: The frontend exposes the routing system to non-technical users, enabling upload/edit of Excel workbooks, running the routing pipeline, viewing maps and metrics, and exporting printable route reports.

How the pieces integrate
- Data flow: Excel/workbook or defaults → `dashboard.py` normalizes data → `geocache.py` geocodes addresses (cached) → `main.py` / `dashboard.py` request a distance matrix from OpenRouteService → Saim's assignment logic groups orders to vehicles/drivers → Abdullah's routing and simulation creates ordered routes and metrics → Divine's UI displays results and exports HTML reports.
- External services and files: OpenRouteService (geocoding + distance matrix) via `requests`; local `geocache.xlsx` to avoid repeated API calls; input workbooks `delivery_data.xlsx` / `fleet_data.xlsx` or uploaded Excel files.
- Primary languages and stack: Python 3, Streamlit for frontend, pandas/openpyxl for data, Plotly + Leaflet for visualization, OpenRouteService APIs for geocoding & routing data.
